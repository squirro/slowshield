How it works

Five simple ideas. One proxy.

  1. 01

    One URL. Every tool.

    Point pip, uv, Poetry, npm, pnpm, Yarn or Bun at SlowShield. Nothing else changes: the same packages, the same commands, the same lockfiles. Developers don't have to think about it — that's the point.

  2. 02

    Fresh releases wait their turn.

    Anything published less than a few days ago simply isn't there yet. Indexes show the newest release that has stood the test of time, latest moves back to it, and a lockfile that pins a too-new version gets a clear answer: try again in 2 days.

  3. 03

    Known malware is blocked within the hour.

    Live advisory streams from OSV / OpenSSF and the GitHub Advisory Database are applied automatically. A malicious package or version is refused with HTTP 451 — every time, even for brand-new packages.

  4. 04

    Every byte verified. Tampering caught mid-stream.

    Each download is checked against the registry's own digests and against the fingerprint recorded the first time anyone fetched it. If the bytes ever change, the transfer is cut off before it completes and your team gets an alert.

  5. 05

    Fetched once. Served fast.

    Verified artifacts land in a local cache: faster installs and CI, calm during registry outages, and far less traffic on the public infrastructure we all depend on.

A very fast caching proxy

Put one next to every team, server and build farm.

SlowShield is also a verified, very fast cache. Each instance is one small container — no database server, no coordination — so run a bunch of them: per office, per region, per CI cluster. Every artifact is fetched from the public registry once, then served at local-network speed.

Later

The hard ones

  • conda, CRAN, Hugging Face, Composer, Julia, Bazel mediumauthor-set or missing timestamps — SlowShield keeps its own first-seen ledger
  • apt, dnf, apk hardsigned indexes — opt-in re-signing with your organisation's key
  • Homebrew, Hex hardsigned metadata — cache, verify and refuse at download
  • GitHub Releases & ad-hoc downloads hardno redirect knob — needs a forward proxy

Why some ecosystems are harder

  • Signed indexes. apt, apk, Homebrew and Hex sign their metadata, so a proxy can't quietly remove a version. It can still refuse the download.
  • Untrustworthy dates. Some timestamps are set by the author or the build (Go commit time, conda builds, Composer). SlowShield records when it first saw each version instead.
  • Exact pins. Maven, Go and Nix resolve exact versions, so a too-new version means a clear refusal rather than a silent downgrade — which lines up with Renovate's and Dependabot's cooldowns.

Beyond package managers

Your editor and your CI run with your keys. Shield them too.

Attackers go where the trust is: extensions that auto-update on every laptop, and CI steps that run with deployment credentials. The same patience protects both.

Editor extensions

An update live for minutes. 3,800 repositories gone.

In May 2026 a stolen publishing token was used to push a malicious update of a popular VS Code extension. Auto-update rolled it out within minutes; it was pulled in under an hour — not before a GitHub employee's machine was compromised and about 3,800 internal GitHub repositories were stolen. The malware advisory came two weeks later. An extension gallery that holds updates back for a few days would have hidden that release for its entire life.

  • Extension gallery for VSCodium, Windsurf and code-server — and VS Code via its enterprise gallery policy — with the same delay, blocklist and integrity checks
  • Ready-made policy packs: VS Code extensions.autoUpdateDelay and AllowedExtensions, Cursor's install cooldown
  • npm and pip installs triggered by extensions and MCP servers (npx, uvx) are covered today

Sources: Help Net Security, Nx Console advisory

GitHub Actions

Same tag, different code.

In March 2025 (tj-actions) and again in March 2026 (Trivy) attackers moved existing version tags to malicious commits. Every workflow using @v1 ran the new code on its next build — with its secrets. Advisories followed hours to days later. A gate that only accepts commits older than your delay, and refuses tags that moved, would have stopped both.

  • slowshield actions check resolves every uses: — including nested composite actions and reusable workflows — and fails on young commits, moved release tags and blocklisted actions
  • SlowShield records when it first saw each tag → commit pair, because commit dates can be forged
  • Runs as a required pull-request check or a self-hosted runner hook; package installs inside steps already go through SlowShield

Sources: Wiz, StepSecurity

Honest limits: nothing that waits longer than your delay before turning malicious is caught by the delay alone — that's what the advisory streams and integrity checks are for. Defence in depth, not magic.

Get started

Up and running before your coffee is cold.

  1. 1 Run it

    git clone https://github.com/squirro/slowshield
cd slowshield/deploy/docker
cp .env.example .env          # your hostname, TLS mode, optional GitHub token
docker compose up -d
# add the Grafana stack: docker compose -f compose.yaml -f compose.observability.yaml up -d
    git clone https://github.com/squirro/slowshield
cp slowshield/deploy/podman/*.{pod,container,volume,network} ~/.config/containers/systemd/
systemctl --user daemon-reload
systemctl --user start slowshield-pod   # rootless, auto-updating
    git clone https://github.com/squirro/slowshield
helm install slowshield slowshield/deploy/helm/slowshield \
  --set hostnames='{slowshield.example.com}' \
  --set tls.mode=acme --set tls.acmeEmail=you@example.com

  2. 2 Point your tools at it

    pip config set global.index-url https://slowshield.example.com/pypi/simple/
export UV_DEFAULT_INDEX=https://slowshield.example.com/pypi/simple/
npm config set registry https://slowshield.example.com/npm/

    Poetry, PDM, Pipenv, pnpm, Yarn and Bun snippets are on the built-in setup page.

  3. 3 Watch it work

    Open the dashboard to see what your organisation installs, which versions are waiting and what was blocked. Add a GitHub token to enable the second advisory stream — SlowShield tells you how, right in the UI.

The story

Built overnight, because we needed it.

In March 2026 the TeamPCP campaign turned trusted security tooling into a delivery mechanism: a compromised Trivy release leaked CI credentials, and within days backdoored packages were landing on PyPI. It came uncomfortably close to us.

That night I built the first SlowShield around one simple rule that would have stopped the whole thing: don't install anything younger than a week. It has protected our teams at Squirro ever since. Now it is open source, so it can protect yours.
