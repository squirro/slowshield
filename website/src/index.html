SlowShield is a free, open-source proxy between your package managers and PyPI, npm, Go and Maven. It holds brand-new releases back for a few days, blocks known malware the moment it is reported and verifies every download. Made for developers and small teams who want supply-chain security that just works, without buying and running an artifact repository manager.

Set it up for your team See how it works ↓

Try it now on your laptop

One container, plain HTTP on localhost, nothing kept after you stop it. The dashboard is at http://localhost:8080.

  1. 1 Start it

    docker run --rm -p 127.0.0.1:8080:8080 ghcr.io/squirro/slowshield:latest

  2. 2 Install something through it

    A throwaway virtualenv, because Homebrew and current Linux Pythons refuse pip installs outside one. Releases younger than a week are held back; known malware is refused with HTTP 451.

  3. 3 Use it for everything

    pip, uv, npm and go then use SlowShield in every new terminal. Remove the lines to switch it off.

Who it's for

Made for developers and small teams.

Large organisations put an artifact repository manager such as JFrog Artifactory or Sonatype Nexus between their builds and the internet, add a repository firewall to keep malware out, and pay people to run it. Most teams can't justify that. SlowShield covers the part that keeps you safe, in one small container you start in a minute, with near-zero upkeep.

  • Free and open source. Free as in free 🍺, and open source under the Apache-2.0 licence.
  • Nothing to administer. No database server, no repositories to configure, no admin team.
  • One policy for every tool. Per-tool settings such as npm's min-release-age help on one machine; SlowShield applies the same rules to every laptop, CI runner and package manager.

Safe by default

A seven-day delay, malware blocking and verification out of the box. Brand-new packages still install (and are flagged) so nobody's day is ruined. Urgent fix? Release a single version early with one line of config.

Advisory streams built in

OSV / OpenSSF malicious-packages and the GitHub Advisory Database sync every hour. Feed health is monitored and alerted on. CVE-aware policies are next on the roadmap.

Tamper-proof

Registry digests plus trust-on-first-use fingerprints, a content-addressed cache that is only written after verification and re-checked on a schedule.

Know what you depend on

A fast dashboard: installs and trends, newly introduced dependencies, versions waiting in line, and a security timeline down to the machine that tried to install malware.

Kind to public registries

One verified download per artifact instead of one per laptop and per pipeline run — with HTTP/2, conditional requests and a shared cache. Open-source infrastructure is a commons; treat it like one.

Observable

OpenTelemetry metrics, logs and traces, with ready-made Grafana dashboards and alerts for blocked malware, tampering, stale feeds and errors.

Hardened all the way down

Distroless Amazon Linux 2023 images, non-root and read-only. TLS 1.3 with post-quantum key exchange and HTTP/3. Strict CSP. Pinned, audited CI. Every release load-tested against the last.

Deploys in minutes

Docker Compose, rootless Podman or a Helm chart. One small container plus Caddy for automatic TLS. No database server — SQLite is embedded.

How it works— without SlowShield— with SlowShield

Without SlowShield

  1. A maintainer publishes 2.4.0.

    A new release of a package you depend on goes up on the registry.

  2. Every machine installs it.

    Within minutes it is on every laptop, CI runner and build that installs or updates. That's how it should be: a real release from the real maintainer.

  3. Someone steals the maintainer's token.

    A phished password, a leaked CI secret or a malicious browser extension, and the attacker can publish as the maintainer.

  4. The attacker uploads 2.4.1.

    It looks like any other patch release. Inside is a payload that runs when it is installed.

  5. Every machine pulls it.

    It is the newest version, so the same machines install it just as fast as 2.4.0, and run it.

  6. Your secrets leave.

    The payload collects tokens, cloud keys and passwords from every machine and sends them to a server the attacker controls. Nobody on your side did anything wrong.

  7. Then your users are next.

    With your publish tokens and keys, the attacker releases a poisoned version of your own package or app, as you, and your users install it. That is how the Shai-Hulud worm spread through hundreds of npm packages, in 2025 and again in 2026.

With SlowShield

  1. Every install goes through SlowShield.

    Point pip, uv, npm, pnpm, Yarn, Bun, go, Maven, Gradle and the rest at it. Same packages, same commands, same lockfiles.

  2. 2.4.1 waits.

    A release younger than the delay (7 days by default) isn't offered yet. A lockfile pinned to it gets a clear answer: try again in 6 days.

  3. Installs get 2.4.0.

    Indexes show the newest release that is old enough, and latest moves back to it. Builds keep working.

  4. The malware is reported, and blocked for good.

    The advisory feeds (OSV and GitHub) usually flag an attack like this within days. From then on 2.4.1 is refused with HTTP 451, even after the delay.

  5. A swapped file is cut off.

    Say someone replaces the file behind 2.4.0. SlowShield checks every download against the registry's digest and the fingerprint it recorded the first time, cuts the transfer off and alerts your team.

  6. Fetched once, served to everyone.

    One SlowShield serves every laptop, runner and build. Each file comes from the registry once and from the cache after that: faster installs, calm during outages, and one download instead of hundreds.

Best practice for teams

Every machine goes through SlowShield. Nothing goes around it.

Run one SlowShield for the team, point every laptop, server and CI runner at it, then close the side doors: only SlowShield may reach the public registries. A forgotten setting or a script with its own index URL can no longer skip the delay or the malware check.

  1. 1 Run one SlowShield for the team

    A small VM or a pod every machine can reach, with a real hostname and TLS (Caddy handles the certificates). Docker Compose, rootless Podman or the Helm chart.

  2. 2 Point every machine at it

    The same three settings everywhere: in each developer's shell, as ENV in your base images, and on every CI job.

  3. 3 Close the side doors

    At the firewall or proxy, allow outbound HTTPS to the registries only from SlowShield, or answer their names in your internal DNS for everyone else. SlowShield itself only needs the registries and its advisory feeds.

Works great with Tailscale

Many SlowShields.
One name.

Run a SlowShield in every region or office and put them all behind one Tailscale Service. Laptops, servers and CI runners on your tailnet use a single URL, and Tailscale sends each of them to an instance that's up. Nothing is exposed to the internet, Tailscale takes care of the HTTPS certificate, and there's no load balancer to run.

  1. 1 Run SlowShield on each host

    docker run -d --restart unless-stopped -p 127.0.0.1:8080:8080 \
  -v slowshield:/data \
  -e SLOWSHIELD_PUBLIC_URL=https://slowshield.your-tailnet.ts.net \
  ghcr.io/squirro/slowshield:latest

    One per region or office, on a small VM or server. Each keeps its own verified cache; they never need to talk to each other.

  2. 2 Put them behind one service

    # on every host, once svc:slowshield (endpoint tcp:443) is defined in the admin console
sudo tailscale up --advertise-tags=tag:slowshield
sudo tailscale serve --service=svc:slowshield --https=443 127.0.0.1:8080

    Hosts need a tag and Tailscale 1.86 or later. Before upgrading a host, drain it with tailscale serve drain; the others take over.

  3. 3 Let your tailnet in

    "tagOwners": {
  "tag:slowshield": ["autogroup:admin"],
  "tag:ci":         ["autogroup:admin"]
},
"autoApprovers": {
  "services": { "svc:slowshield": ["tag:slowshield"] }
},
"grants": [{
  "src": ["autogroup:member", "tag:ci"],
  "dst": ["svc:slowshield"],
  "ip":  ["443"]
}]

    Add this to your tailnet policy file, then point the shell settings above at the service URL. GitHub-hosted runners join for one job with the Tailscale GitHub Action.

Tailscale Services is available on every Tailscale plan. Sending each client to its nearest instance uses Tailscale's regional routing (Premium and Enterprise plans, switched on in the admin console). Without it, all clients use one instance and move to another if that one goes away.

Agent sandboxes

Good for humans and agents.

Don't let your autonomous agents trip into supply-chain attacks. Coding agents run pip install, npm install, npx and uvx on their own, and nobody reads the output. Give their sandboxes the same SlowShield as your laptops.

  • Agents reach for the newest version. They often start from a fresh sandbox without a lockfile, so every run resolves latest again. SlowShield answers with the newest release that is at least a week old.
  • Hallucinated names get squatted. Models invent plausible package names, and attackers register them. A name registered this week is held back like any other brand-new release.
  • Nobody watches the install. Install scripts run unattended. Known malware is refused with HTTP 451 and recorded with the client that asked for it, so you can see what an agent tried to install.

  1. 1 Set it in the sandbox image

    # Dockerfile of the agent's sandbox, devcontainer or CI image
ENV PIP_INDEX_URL=https://slowshield.example.com/pypi/simple/ \
    UV_DEFAULT_INDEX=https://slowshield.example.com/pypi/simple/ \
    npm_config_registry=https://slowshield.example.com/npm/ \
    GOPROXY=https://slowshield.example.com/go

    pip, uv, npm, npx, uvx and go all read these, so the agent needs no instructions.

  2. 2 Let only SlowShield out

    # network allowlist of the sandbox (the syntax depends on the sandbox)
slowshield.example.com
# leave out pypi.org, files.pythonhosted.org, registry.npmjs.org, proxy.golang.org and sum.golang.org

    With the registries off the allowlist, an agent can't install around SlowShield, even when it passes its own --index-url.

Get started

Up and running before your coffee is cold.

Run it for your team

Images: ghcr.io/squirro/slowshield and ghcr.io/squirro/slowshield-caddy, for amd64 and arm64, each with an SBOM and build provenance attached. Pin a release (:0.0.6) or a digest in production.

  1. 1 Run it

    git clone https://github.com/squirro/slowshield
cd slowshield/deploy/docker
cp .env.example .env          # your hostname, TLS mode, optional GitHub token
docker compose up -d
# add the Grafana stack: docker compose -f compose.yaml -f compose.observability.yaml up -d
    git clone https://github.com/squirro/slowshield
cd slowshield/deploy/podman
mkdir -p ~/.config/containers/systemd ~/.config/slowshield/certs
cp -r quadlet/. ~/.config/containers/systemd/
cp examples/config.toml examples/slowshield.env ~/.config/slowshield/
$EDITOR ~/.config/slowshield/slowshield.env   # hostnames, TLS mode, public URL
systemctl --user daemon-reload
systemctl --user start slowshield-pod   # rootless, auto-updating
    git clone https://github.com/squirro/slowshield
helm install slowshield slowshield/deploy/helm/slowshield \
  --set hostnames='{slowshield.example.com}' \
  --set tls.mode=acme --set tls.acmeEmail=you@example.com

  2. 2 Open the Setup page

    Open /ui/setup on your instance's hostname (https://slowshield.example.com/ui/setup), or Setup in the dashboard's menu. It shows how to point each tool at your instance, with its address already filled in: four lines for your shell profile that cover pip, uv, npm and go; settings for Poetry, PDM, Pipenv, pnpm, Yarn, Bun, Maven, Gradle, sbt and Coursier; and what to use in CI and containers.

  3. 3 Watch it work

    Open the dashboard to see what your organisation installs, which versions are waiting and what was blocked. Add a GitHub token to enable the second advisory stream — SlowShield tells you how, right in the UI.

The story

Built overnight, because we needed it.

In March 2026 the TeamPCP campaign turned trusted security tooling into a delivery mechanism: a compromised Trivy release leaked CI credentials, and within days backdoored packages were landing on PyPI. Mere minutes after one went live, one of our build servers pulled it. We caught it quickly and contained it before any lateral movement, but it was too close for comfort.

That night I built the first SlowShield around one simple rule that would have kept those packages off our machines: don't install anything younger than a week.

Yes, many package managers now have built-in delay settings. They are a great way to start, but I don't even trust myself to always have them set up.

So SlowShield has protected our teams at Squirro ever since. It has served millions of package downloads, and its cache has saved us terabytes of bandwidth. Along the way it also learned to block known malware, verify every download and show what gets installed where.

Now it's open source, so it can protect your team too.

SlowShield is maintained by the team at Squirro, which builds enterprise AI search and GenAI solutions for regulated industries.
